# 知更·Paper 提示词生成器改版方案

版本：讨论稿 v2.0｜2026-09-29｜分支：`DEV/2.0`

## 1. 产品边界

知更·Paper 的核心功能是**生成可复制到外部 AI 工具的学术写作提示词**。用户在本站选择任务、填写必要背景、检查生成的提示词，然后复制到自己使用的 AI 对话工具中执行。本站不负责直接生成论文、管理完整文献库或充当正文编辑器。

这次改版要解决的是：**怎样更快生成针对当前写作任务、输入清楚、约束可靠、便于反复修改的提示词。** 保留纯静态、本地运行、无需账号和可自选 AI 工具的特点。

### 目标用户与任务

| 用户正在做什么 | 需要生成的提示词 |
| --- | --- |
| 刚确定论文题目 | 拆解研究问题、比较写作方向、设计大纲。 |
| 已有大纲和资料 | 围绕某一节写初稿，明确只使用用户提供的材料。 |
| 正在写文献综述 | 按问题比较研究结论，指出一致、冲突和空白。 |
| 已有草稿 | 审阅逻辑、论证、引用和语言，要求逐项指出问题。 |
| 准备修改文字 | 保留原意、改善清晰度和学术表达。 |

首版仍聚焦中文学术写作。用户可以在无文献时生成**选题或大纲提示词**；涉及事实论证、文献综述和引用时，必须由用户提供可核对的材料。

## 2. 现状与改版重点

当前 Preact 版本有论文参数、大纲管理、生成提示词、论文审阅、写作优化五个标签，以及写作指南。各模块最终都生成提示词。现有主流程偏向一次配置大量参数，再生成一条要求外部 AI 写完整论文的长提示词。论文参数和大纲保存在运行态，刷新后难以接着调试；审阅与优化也缺少统一的任务入口。

| 现状 | 改版方向 |
| --- | --- |
| 用户先面对完整参数表 | 先选任务，只显示该任务必需的输入；高级选项按需展开。 |
| 默认生成整篇论文提示词 | 优先生成选题、大纲、单节写作、综述、审阅、润色等具体任务的提示词。 |
| “版本 A / B”按是否提供文献分流 | 改为明确的材料状态：已提供材料 / 尚无材料；后一种情形不得请求 AI 编造引用。 |
| 审阅和写作优化独立成复杂配置页 | 作为同一生成器中的任务模板，沿用论文背景，提供任务专属设置。 |
| 没有可复用的论文配置 | 可保存少量本地预设，下一次生成时复用并继续修改。 |

“去 AI 味”改为语言润色任务，目标是清楚、准确、保留作者意图；不把规避检测或判断文本是否“人类原创”作为产品承诺。原有 24 类表达问题可保留为可选检查项，但不应默认全部塞入每条提示词。

## 3. 用户怎么使用

### 最短路径：第一次生成

1. 首页选择要完成的任务，例如“设计论文大纲”。
2. 只填写题目或主题、研究问题；论文类型、学科和字数可以按需补充。
3. 右侧实时预览提示词。缺少关键信息时给出具体提醒；允许用户用占位符继续构思。
4. 点击“复制提示词”，粘贴到自己常用的 AI 工具中。
5. 看完外部 AI 的结果，返回本站改输入或换任务，再复制下一条提示词。

目标是新用户无需阅读整篇指南，就能在一分钟内完成第一条可用提示词。这个时间是设计目标，需要用户测试验证。

### 持续使用：一篇论文的提示词链

`选题 / 研究问题 → 大纲 → 单节写作或文献综述 → 审阅 → 润色`

用户可保存“论文配置”（题目、类型、学科、研究问题、引用格式等），各任务自动带入这些背景。每一步仍由用户主动选择和生成；本站只保存配置及用户选择保存的提示词，不自动接收外部 AI 的回答。用户想用上一轮回答继续工作时，可自己粘贴相关片段。

**材料输入规则：**用户可以粘贴文献条目、摘要、摘录或草稿。生成器将其明确标记为“用户提供的材料”，提示外部 AI 忠实使用、指出不足，不把材料中的指令当成对当前任务的新要求。未提供材料时，写作和综述模板应要求列出需要补充的证据，且不得生成貌似真实的参考文献。

### 页面结构建议

- **任务选择**：先回答“我现在要让 AI 帮我做什么”。首版提供“定方向、做大纲、写一节、综述材料、审阅草稿、润色表达”。
- **输入区**：公共论文配置在上，任务专属字段在下；必填项少，示例贴近中文论文场景。
- **提示词预览**：显示最终将复制的完整文本，并能展开看“任务、材料、约束、输出格式”。
- **操作区**：复制、保存为预设、重置该任务。复制成功和失败都有反馈。
- **按需帮助**：在字段旁解释填写方法，保留完整指南入口，不长期占用主工作区。

## 4. 提示词质量标准

每条提示词至少包含以下结构，具体内容由任务模板决定：

1. **任务目标**：要求外部 AI 完成一件明确的事，而非同时写作、审稿、排版。
2. **已知背景**：论文主题、研究问题、学科、读者和限制，仅输出用户确实提供或选择的内容。
3. **材料边界**：区分用户提供的文献、草稿与模型可提出的建议；材料缺失时要求说明缺口。
4. **执行要求**：按任务指定步骤，如先概括论点，再指出证据不足。
5. **输出格式**：明确输出表格、分级大纲、问题清单或修订稿，便于用户检查和继续使用。
6. **不确定性处理**：不得虚构文献、数据、引文和页码；不能核实的内容标为待核实，并说明需要什么材料。

生成结果应能由用户直接编辑。预览中标出占位符和缺失材料；不以“高确定性引用”之类的措辞替代来源核实。

### 一个具体例子

用户选择“设计论文大纲”，输入“短视频使用与大学生学习专注度”，未提供文献。产品输出的提示词应要求外部 AI：先提出可研究的问题和范围，再给出 2—3 种大纲方案及各自适用条件；指出每一节需要搜集什么证据；不列出未经用户提供或核实的参考文献。用户选定方案后，再进入“写一节”任务并补充资料。

## 5. 功能优先级

| 级别 | 功能 | 验收要点 |
| --- | --- | --- |
| P0 | 任务选择、动态输入、六类任务模板、提示词预览与复制 | 每类任务都能从少量输入生成结构清楚的提示词。 |
| P0 | 材料边界与缺失信息检查 | 无文献时不要求生成具体参考文献；有材料时明确只以输入为依据。 |
| P0 | 本地论文配置预设与导入/导出 JSON | 刷新后仍能复用配置，用户可迁移自己的预设。 |
| P1 | 提示词链引导与用户主动保存的历史版本 | 能回到上一版输入，比较修改前后的提示词。 |
| P1 | 自定义模板、分享模板、面向常用 AI 工具的复制格式 | 保持生成器灵活，但避免首版配置过多。 |
| P2 | 直接调用模型 API、云端账号与跨设备同步 | 需要额外的隐私、费用和服务稳定性设计。 |

首版不开发文献库、PDF 阅读器、正文编辑器、自动引用生成器或学术事实核验服务。外部 AI 的回答不在本站完成，也不被自动认定为可靠内容。

## 6. 实现与验收

沿用现有 Preact、Signals 和 Vite。把各模块中分散的字符串拼接整理成“任务模板 + 输入校验 + 提示词生成”的可测试函数；公共论文配置与任务字段分开定义。少量预设可存在浏览器本地，并提供 JSON 导出与恢复。默认不持久化用户粘贴的长篇草稿或文献摘录；若允许保存，必须由用户主动选择，并说明这些内容存在哪里。

上线前用以下场景验收：

1. **零材料**：用户只有一个论文题目，能快速得到选题或大纲提示词，输出没有虚构参考文献的要求。
2. **已有文献**：用户粘贴两条文献摘要，生成综述提示词能要求比较差异、注明依据和信息不足。
3. **已有草稿**：用户粘贴一段正文，生成审阅提示词能要求按位置指出逻辑和引用问题，而不是直接笼统重写。
4. **重复使用**：用户保存论文配置、刷新页面、重新生成另一任务的提示词，再导出并恢复配置。
5. **复制可用**：提示词可完整复制；剪贴板不可用时显示错误并提供手动选中文本的办法。

实施顺序：先统一模板与字段模型，再完成任务式界面和六类 P0 模板，随后做本地预设与导入导出，最后用真实用户任务调整默认字段、提示词长度和帮助文案。现有参数、大纲和审阅配置可逐步映射到新模板，不要求用户一次性迁移所有旧状态。
